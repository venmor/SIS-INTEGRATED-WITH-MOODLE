# Security

Do not commit secrets, tokens, private keys, production credentials, real student data, or unapproved institutional policy values. Use fictional, resettable fixtures only.

Report a suspected exposure or security weakness privately to the project owners. Do not publish exploit details, credentials, or sensitive records in issues, pull requests, task packets, learning notes, or demos.

Security, privacy, permissions, official-record integrity, audit and recovery controls in the handbook override convenience or implementation assumptions.
