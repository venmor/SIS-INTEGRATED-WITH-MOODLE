# Student workspace — UI-011 bounded design

The 15 October 2026 user direction replaces the student top navigation with the selected staff-like emerald left rail. This changes presentation within existing student workflows. It does not alter student authority, registration policy, official records or approved source history. Lead Charles Hangoma; reviewer Chitindu Milimbo.

On desktop the viewport contains an emerald navigation rail, a white context bar and a pale independently scrolling workspace. The rail contains the student brand, visible student-workspace context, goal-based links to existing routes, then an account identity/footer outside the navigation scroll region. Navigation and workspace can scroll independently while the account remains visible. One main landmark contains the page. A student-local effect resets workspace scrolling on route changes. The white bar offers the real `/workspaces` route without a second top navigation menu.

On mobile the rail becomes a compact student header with the existing keyboard-accessible Portal sections disclosure, account identity and natural document scrolling. Links retain active-page semantics, focus outlines, readable text and minimum touch targets. No fixed overlay obscures forms. Printing removes navigation and scroll clipping. No external fonts, images, animation or icon package is needed.

Home keeps the authoritative current-period registration state first, including a distinct unavailable state. A General information record surface shows only the existing own-student number, programme, intake, campus and study mode. Real current-period registration, onboarding and correction data retain their source meanings. The account/configured-period board does not claim to summarize a selected historical programme attempt. Existing readiness, finance, study and support actions stay real, with corrections/contact forms below their records.

The published timetable retains server-validated own-course sessions and changes, date-only scoped recovery, CAT dates/times and bounded pagination. A compact overview summarizes sessions, distinct courses and session start dates from the complete current filter, before pagination; it never counts historical changes as current sessions. A session crossing midnight is counted once under its CAT start date. Publication version, period, published and checked dates stay visible. A restrained segmented week/day/list control and dated day panels improve scanning. No-calendar-data and missing-course states retain their honest next steps. The list remains the low-bandwidth and accessible alternative to day/week grouping. It does not invent activities, a full institutional calendar, clash resolution or official publication.

The shell parses the same validated academic context as the existing portal. Readiness, course planning, registration and timetable links preserve attemptId/period. Home, finance, results, notifications and support keep their existing source scopes; a finance period is not silently reinterpreted as an academic registration context. Switch workspace deliberately opens `/workspaces`.

Verification uses the real Next page/components against an explicit loopback fixture API, never a database/provider, to show regression failures then passing behavior. The same suite continues to test malformed, foreign, unavailable, pending, historical and publication states. Final coordinated preview inspection adds connected fixture journeys, desktop/mobile screenshots, axe checks and full release regression under the release lead. Source coverage, automated checks and human acceptance are reported separately.
