## How development is happening

- `development/` is an npm workspace: Next.js portal and same-origin proxy → NestJS owning module → Prisma/PostgreSQL. Shared contracts, configuration, UI and fictional fixtures live under `packages/`.
- The handbook is controlling design. Task packets link exact requirements/actions/permissions/UI/recovery/tests; gaps record missing authority. Demo configuration is explicitly fictional and cannot establish institutional approval.
- Database transactions, optimistic versions, idempotency receipts, audit and outbox records carry formal decisions. Moodle transport is separate from registration truth; payment delivery is separate from ledger/clearance truth; results publication is separate from raw marks.
- Existing development uses vertical slices and learning/rotation ledgers. Historical “uncommitted on main” wording in reviews is not reliable current Git status. This audit records the actual baseline and fresh proof separately.
- CI defines pinned Node, clean build, source/script/lint/unit checks, PostgreSQL migration/seed/API suites and Playwright against a fresh browser database. Its configuration is present; this run did not trigger or prove remote CI.

## Findings addressed in this continuation

1. Package list/detail queries now enforce offering/period or preparer scope; technical operators cannot browse academic package evidence.
2. Assembly requires each candidate's complete numeric component set; absent or exceptional values are not manufactured as zero.
3. Canonical hashing survives PostgreSQL JSONB object-key ordering. Packages freeze source/component references; legacy incomplete snapshots require reassembly and approval.
4. Publication and amendment are atomic, scope/version checked and independent of preparer/marker/requester. Current candidates and official registrations are rechecked. Shared offering serialization covers moderation/candidate/plan writers; eligibility rows are held through commit.
5. SQL protects released batches/results and their package evidence. The review caught and corrected a delete-trigger bug that also prevented removal of unpublished packages.
6. The student projection uses the actual conversion role (`STUDENT` with `study`), resolves person ownership server-side, applies mark visibility and excludes internal deliberations.
7. Amendments preserve original official versions and create explicit downstream review records. They do not calculate progression or silently alter finance, registration or Moodle.
8. Lost-response UI retains the same command key/payload, including malformed/truncated JSON responses. Queues paginate, and authorized amendment detail is loaded directly instead of disappearing behind the first100 releases.
