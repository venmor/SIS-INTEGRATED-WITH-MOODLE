# Phase 3–5 integrity repair — 2026-09-24

The audit found three gaps: an offer extension changed the current deadline without a retained terms version; registry could approve an addition after checking capacity alone, leaving charges stale; and a payment reversal deleted allocations. The repair adds offer-term revisions, approval-time academic checks plus Finance-owned charge/clearance reassessment, and allocation compensation records. The existing official registration snapshot remains immutable. Demo timetable collision groups are explicit fictional controls; GAP-021 records the institutional timetable gate.

Student-facing checks: `/applicant/<application-id>/offer` displays the offer version and current deadline; `/student/changes` shows pending/approved course requests, `/student/finance` shows charge and clearance effects. Finance staff use `/admin/finance`; Registry uses the existing amendment decision route. Historical allocation compensation is visible in the database/API tests; there is no student-facing ledger-history screen for it.

Test evidence and localhost status are recorded in `VERIFICATION.md`. These repairs do not imply phase acceptance, production provider approval, real timetable publication, step-up authentication or human walkthrough completion. Existing pre-repair deleted allocation rows cannot be reconstructed automatically.
