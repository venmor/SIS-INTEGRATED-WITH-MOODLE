# Finance reconciliation workbench — 2026-10-03

[TASK-V2-FIN-001](../task-packets/TASK-V2-FIN-001.md) addresses an unbounded Finance Officer case query and a finance home that fetched three full lists only to show task counts. The home now asks the finance module for source-owned counts of open/escalated reconciliation cases and requested adjustments/arrangements. A Finance Approver sees the latter two counts without gaining case access. The counts are current operational workload indicators, not certified financial reports.

The reconciliation queue uses database-side, bounded `(createdAt,id)` traversal with status and oldest/newest choices. Its signed cursor is bound to actor, selected live appointment, status and sort. A stale, changed or tampered cursor returns a safe restart state; URL filters survive page navigation. The queue displays count, state and next step at desktop and mobile widths. It opens each case for its existing individual resolution flow, with no bulk money action.
