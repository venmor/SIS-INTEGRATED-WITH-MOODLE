# Controlled academic-support closure — 2026-10-04

[TASK-V2-SUPPORT-005](../task-packets/TASK-V2-SUPPORT-005.md) closes a synthetic academic-support case only after an appointed adviser selects a supported, evidenced reason. A guidance or course-plan closure requires an adviser reply; agreed-action completion requires a confirmed student action. Any proposed, accepted or student-claimed action blocks closure. Other handbook closure reasons depend on referral, handover, no-contact or observation workflows and are not offered here.

The API rechecks the selected role, effective appointment, current adviser relationship and demo-only service. It serializes closure with new replies and proposals on the request row, then writes a single immutable closure, a request event, audit and closed status in one transaction. An idempotent retry returns the original receipt; a changed reason or stale state is rejected. New replies and actions stop after closure, while the student retains access to the case history and sees a respectful completion message. The bounded assigned queue can filter completed cases; actions leave the open follow-up worklist when completed, and an unfinished action blocks case closure.

This is a partial TASK-042 lifecycle. It does not send a notification, book an appointment, transfer ownership, reopen a case or activate institutional support. [GAP-V2-002](../gaps/GAP-V2-002-student-support-routing-and-ownership.md) remains open. Verification evidence is recorded in [VERIFICATION](VERIFICATION.md); the migration was applied only to the isolated synthetic review database. No provider call or download occurred.
