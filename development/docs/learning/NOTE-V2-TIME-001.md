# V2-TIME-001 — truthful student timetable availability, 2026-10-02

The student portal now links to **My timetable**. Before formal registration it points to registration. After registration it lists only the student's official registered courses and says that class times, rooms and links have not been published. Service failure has a separate message from an ordinary publication wait. The API adds `publicationStatus: AWAITING_PUBLICATION` and a read timestamp to its existing registered-course response; it does not create or return fictional sessions. The route uses the current server session and owner gate, with no browser-stored timetable data.

The API test was red before the status contract existed, then the registration e2e suite passed **13/13** on the isolated synthetic PostgreSQL database. Its cases include pre-registration 404, post-registration source roster, no invented sessions and neutral foreign-student denial. API and web production builds and `npm run typecheck` passed. The student portal browser journey passed **1/1**, including before/after registration and a 390px viewport. See [packet](../task-packets/TASK-V2-TIME-001.md).

This is an availability/registered-course increment, not a published teaching timetable. [GAP-021](../gaps/GAP-021-real-timetable-validation.md) remains open: schedule sessions, venue registry, conflict detection, publication authority/versioning, changes, exams and exports are still absent. Manual screen-reader/low-bandwidth review and human acceptance remain open. No package, image, provider or dataset download was needed.
