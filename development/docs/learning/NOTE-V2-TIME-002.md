# V2-TIME-002 — timetable conflict core, 2026-10-04

[TASK-V2-TIME-002](../task-packets/TASK-V2-TIME-002.md) adds a pure validator for dated teaching occurrences. A caller supplies a versioned rule set (room turnaround, directed campus travel times and draft size limit) plus source-derived venue, teacher and registered-student identities. It reports stable issue codes with occurrence references, not student names. It blocks invalid or timezone-free times, duplicate occurrence IDs, missing venue/teacher, capacity and step-free-access mismatch, room overlap/turnaround, teacher/student overlap and insufficient or undefined cross-campus travel. The validator does not read or write official SIS data.

The initial five tests were observed red against an empty validator; four failed on real conflict cases. They passed after implementation. Further timezone/teacher and non-existent-calendar-date tests failed before those checks were added. The final focused suite passed **8/8**; the full API unit run passed **317 with 13 skipped**. The API production build, lint, source scan, formatting and diff-integrity checks passed. Lint retains unrelated existing warnings. No external data, dependency download or provider call occurred.

This is a foundation only. It does not close GAP-021 or TASK-101–105. The next connected slice must create authoritative course-offering/section and venue identities, reconcile legacy course-only registrations without guessed delivery scope, expand recurrence into dated occurrences, enforce live appointments and independent publication, and project only published versions to each registered student. `GET /registration/timetable` continues to say `AWAITING_PUBLICATION` until that chain is implemented and tested.
