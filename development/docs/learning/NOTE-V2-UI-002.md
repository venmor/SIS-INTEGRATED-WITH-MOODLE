# V2-UI-002 — Admissions workbench presentation, 2026-10-02

The prior queue placed a full live status block in every case row. That made a 50-case page repetitive and difficult to compare, while a failed client refresh left old rows without a clear stale-data warning. The pool filter reset could also show “All states” although the pool is always limited to Submitted cases. The approved `UI-TABLE-001`, `UI-FILTER-001`, `UI-LOAD-001`, `UI-STATUS-001` and permission/recovery records require comparable columns, labelled mobile records, clear applied filters, truthful freshness and immediate response to lost authority.

The existing shared `DataTable` now accepts an opt-in wider card breakpoint for sidebars. The admissions queue uses a desktop table with reference, state/reason/next action, open requests, owner/update and explicit actions; at 900px and 390px the same data appears as labelled cards. The toolbar states the active view and scope; unapplied filter edits and the absence of optional filters are visible. Pool reset retains its mandatory Submitted state. A failed network refresh keeps the previous page, marks it as potentially outdated and blocks claim/release until a successful reload. A 401/403 clears loaded rows and actions instead of retaining them after authority loss. The shared context bar now renders role and scope in readable words; the underlying authorization values are untouched. No export, batch action or policy rule was added.

The new browser test was red before implementation because no table existed. After implementation, the full connected admissions suite passed **5/5** (claim→case, pagination, invalid cursor recovery, scoped reference search and table/card/stale/revocation behavior). A focused rerun after the final copy/context change passed **1/1**. Production web build, API/web typecheck, web lint, source scan and `git diff --check` passed. Synthetic desktop and 390px captures showed readable actions and no horizontal overflow. The isolated `sis_v2_review_20261002` database was used; no real records, downloaded data or external provider were involved.

Manual screen-reader, keyboard-only and low-bandwidth staff acceptance remain open. The visible table is a presentation of the existing bounded server projection; it does not prove institution-wide workload allocation, batch preparation or operational scale under concurrent staffing.
