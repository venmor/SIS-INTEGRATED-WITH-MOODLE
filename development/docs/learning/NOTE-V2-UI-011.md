# Student workspace and timetable presentation

The user's 15 October 2026 direction replaces the student top navigation with the selected emerald sidebar. [UI-011](../task-packets/TASK-V2-UI-011.md) and the [bounded design](../design/STUDENT-WORKSPACE-UI-011.md) record this application-local supersession of the earlier student placement rule; original handbook approvals remain unchanged. Lead Charles Hangoma; reviewer Chitindu Milimbo. Human visual acceptance is pending.

Desktop students now use the same calm rail, white context bar and pale workspace proportions as staff. The navigation and workspace scroll independently; the authenticated account identity and existing Switch account action sit outside the navigation scroll region. Mobile retains the keyboard-accessible Portal sections disclosure and natural document scrolling. Switch workspace opens the deliberate `/workspaces` chooser. Readiness, course, registration and timetable links retain validated academic context. An invoice period is not forwarded as an academic registration selection.

Home keeps confirmed, unregistered and unavailable registration states distinct. General information groups the existing own-student number, programme, intake, campus and study mode. Dates, onboarding counts, corrections and actions remain source-backed. The home endpoint describes the configured current period; this presentation does not claim it represents a selected historical attempt. No fabricated tasks, charts, risk labels, confidential support details or completion totals were introduced.

The published timetable keeps server-projected sessions and historical changes distinct. Its overview counts all filtered current sessions, distinct courses and session start dates before the ten-record page limit. A session crossing midnight is counted once under its CAT start date. Week/day/list controls, dated day panels and session facts share the student presentation. CAT times, source/check dates, incomplete-course publication, bounded paging and the accessible list alternative remain. Malformed or mismatched entitlement/publication data still fails closed; a failed refresh retains only the scoped last-confirmed date. A nested main in the student error fallback was replaced by a named section so the shell provides one main landmark.

Data/API/audit boundary: the shell adds an authenticated, no-store read of the existing `/auth/me` endpoint for the account footer. Existing student records, registration and timetable reads/handlers remain authoritative. No endpoint, schema, role, policy, official record, audit event, provider or business mutation was added by UI-011. The workspace-entry/session increment is separately documented as UI-012.

The final focused rerun added five WCAG 2 A/AA and WCAG 2.1 AA axe scans: desktop/mobile sidebar, mobile published overview, and mobile/desktop home with registration unavailable. All scans reported zero violations; the three cases passed (`.local-release/student-ui-011-accessibility.log`). The scroll case verifies independent rail/workspace movement and a stationary visible account at 1280×500. Mobile navigation uses keyboard activation and preserves exact attempt/period links without horizontal overflow. The overview case verifies 12 sessions before pagination, then 2 sessions after a week change, and zero for an unscheduled registered course. The home case proves an active student record does not become false registration completion when that status read fails.

These browser cases use actual Next components with an explicitly synthetic loopback fixture API on ports 3170/3171. They do not open a database or provider and do not prove live authorization, registration or publication.
