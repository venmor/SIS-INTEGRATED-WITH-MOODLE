# Deferred features and explicit gates

Deferred means assigned to a later slice with a closure condition; it does not mean excluded from the intended SIS.

| Feature | Target | Gate/reason |
|---|---|---|
| Actual result-release browser flow | MVP closure TASK-002–004 | Reviewed IAM step-up and approved release policy/authority, independent of test overrides |
| GPA/progression/carry/repeats/supplementary/lab exemptions | v1.1 TASK-014 | Approved effective-dated academic rules and complete historical sources |
| Complete timetable and exam management | v1.2 TASK-101–116 | Real offerings/resources/periods, scheduling authority, SET privacy and examination custody policy |
| Automatic timetable optimization | TASK-106 optional advanced slice | Approved ADR and constraint policy; manual scheduling must already work |
| Full result appeals and downstream impact decisions | v1.1 and owner-domain releases | Approved admissibility/deadlines/authority; impact-review task is not a computed decision |
| Postgraduate end-to-end | v1.1, v1.2, v1.6 | Research/ethics/examiner/award decisions remain separate |
| Protected student support | v1.4 TASK-041–045 | Consent, privacy, safeguarding, independent discipline and service ownership |
| Student AI assistance | v1.4 pilot → v2.0 TASK-121–127 | Explicit use-case/ADR/provider/privacy approval, cited knowledge and adversarial evidence; regular help remains available |
| Advanced reporting AI | TASK-075 separate optional capability | Governed metric layer and approved model register; no unrestricted queries or autonomous decisions |
| Real provider activation and legacy migration | v1.8 | Approved contracts, isolated reconciliation/drills and cutover authorization |

No timetable, examination, support or student-AI request is silently dropped. The detailed backlog and maturity matrix show its delivery target and evidence gate.
