# Product roadmap

The immediate v2 milestone is a **synthetic operating-university demonstration**: authorized users configure fictional, versioned policies and structure in the UI, then exercise connected workflows against those records. A real timetable or institutional dataset is unnecessary for this milestone. Simulator and provider boundaries must be plainly labelled; production use still needs institutional decisions, real integrations and operational acceptance. See the demonstration completion direction in the [implementation backlog](../../plan/feature-sis-expansion-2.0.md).

The detailed executable backlog is [feature-sis-expansion-2.0](../../plan/feature-sis-expansion-2.0.md). It extends the approved release families with source-linked vertical slices, file targets, dependencies, user journeys and measurable exit gates.

The [operating-SIS v2.0 design](../superpowers/specs/2026-10-02-v2-operating-sis-design.md) and [execution plan](../superpowers/plans/2026-10-02-v2-operating-sis-plan.md) sharpen this backlog with configurable institution setup, high-volume admissions navigation/allocation, class attendance, localized workflows, persistent guardrailed student AI, trustworthy exports, and explicitly real provider-backed payment boundaries. Institutional setup authority remains an open design gap. The user lifted the limited-data restriction on 2026-10-02; substantial transfers and paid services still need a stated size/cost before use. Generated synthetic records remain the data boundary.

**2026-10-07 continuation:** [SETUP-003](../task-packets/TASK-V2-SETUP-003.md) supplies explicit fictional proposer/independent-approver authority, immutable structure/calendar versions and a working setup UI. Its source projections preserve legacy registration windows; programme/curriculum and domain policy adoption remain separate owner handoffs. [Moodle setup](../demo/MOODLE-CLOUD-CONNECTION-SETUP.md) now records an authenticated read-only cloud identity check and owner-reported token retirement. [MOODLE-001](../task-packets/TASK-V2-MOODLE-001.md) preserves pending SIS work without consuming retries or claiming access while persisted live prerequisites are missing. Simulator delivery remains available. Full live provisioning and grade/calendar exchange are still pending; read-only connectivity does not complete those workflows.

**2026-10-12 timetable continuation:** [TIME-007](../learning/NOTE-V2-TIME-007.md) verifies the defined fictional registration-to-section manifest, independent current-source publication, atomic replacement, uncertain-response recovery and the student's own classes/changes. [Student presentation](../learning/NOTE-V2-TIME-UI-001.md) includes bounded CAT views and scoped date-only outage recovery. The [walkthrough](../demo/TIMETABLE-PUBLICATION-WALKTHROUGH.md) retains human acceptance as pending. This closes the bounded synthetic publication behavior, not every timetable task.

Next dependencies: (1) complete typed programme/curriculum and institution-scale section allocation/configuration; (2) implement the notification owner's publication handoff, broader timetable/lecturer/exception journeys and operational acceptance; (3) persisted Moodle run, manifest, fresh approval and durable claim foundations before any course/enrolment/group write. Continue examination, attendance, risk/support, AI, finance-provider and reporting slices against their source-linked contracts. None is closed by adding a navigation link or a synthetic success response.

First accept the integrated presentation MVP. Then deliver v1.1 academic depth; v1.2 teaching, timetable, examinations and Moodle; v1.3 finance; v1.4 protected support and a governed student-AI pilot; v1.5 quality/governance; v1.6 research completion, graduation and credentials; v1.7 reporting/regulatory; v1.8 production integrations; v2.0 operational acceptance.

Postgraduate delivery is deliberately distributed across candidature (v1.1), proposal/ethics (v1.2) and examination/completion (v1.6). SET participation proof is an early QA dependency of examination slips. Student AI and optional timetable optimization require their own approved ADRs and cannot bypass official decisions.
