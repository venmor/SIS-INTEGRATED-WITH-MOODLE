## Implementation contract

1. Repair package query scoping and incomplete per-student component calculations before publication. Freeze component/CA/policy references in each package; legacy packages lacking a reproducible snapshot must be reassembled and approved.
2. Add assessment-owned immutable release batches and official result versions. Release requires the active examinations assignment with explicitly granted `release-results`, matching period, an independent preparer/marker, approved package, correct candidate identities, release-policy readiness, exact reviewed version and declaration. No lecturer, tutor, Moodle administrator or system administrator release.
3. Serialize publication by offering/period. One atomic transaction writes the complete batch, result versions, safe portal notifications, audit, command receipt and outbox. Duplicate keys return the original receipt; changed payloads conflict. Notification delivery is asynchronous and cannot undo publication.
4. Student reads resolve identity from the authenticated account, return only that student's published versions, record access, and omit component evidence, internal reasons, board notes and other students. No export endpoint is introduced.
5. Amendment skeleton: examinations requests replacement of a published batch using a newly moderated/board-approved package, reason and evidence reference. A distinct authorized release officer approves. Preserve every old version, link new versions to predecessors and mark downstream readiness for authorized review. Never edit registrations, finance, credentials or Moodle from assessment.
6. Render full-page review/release and amendment controls, exact version/consequence/declaration, safe error and uncertain-outcome recovery, student result history and a discoverable student navigation link.

## Security integration gap

The merged IAM code now has TOTP challenges, but its verified challenge is account/action-bound only. It does not meet publication's session, purpose, target/version and command-digest binding or transactional consumption. Keep the step-up port fail-closed; never infer MFA from a role, fresh sign-in, client boolean or `DEMO_MODE`. Default publication/amendment approval refuses until IAM supplies a verified, purpose/target/version/session-bound single-use proof within the transaction. Isolated tests may supply a test verifier. That proves domain behaviour, not a complete browser release demo. See GAP-PH7-CONTINUATION.
