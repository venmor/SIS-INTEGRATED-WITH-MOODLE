## Intended behavior and interim decision

Every valid SIS source action still commits its source record and canonical outbox event atomically. For either a configured `live-test` or a refused requested live configuration, delivery/provisioning/reconciliation and mapping draft/test/activation commands return a typed, non-failure `NOT_PROVISIONED` result **before** creating/incrementing a delivery attempt, taking a lease, creating/activating a mapping, recording an external success/failure, or calling Moodle. Existing attempt/history values remain untouched. A deferred source is neither delivered, retried, dead-lettered nor manually failed. Synthetic mapping checks and old simulator `ACTIVE` records cannot prove live readiness; mapping commands retain their active role, kind/existence, separation-of-duties and test-required validation before deferral.

This increment deliberately closes **every live write/reconciliation gate**. Static configuration, a matching target identity, a role, an environment run ID or a prefixed reference cannot open it. There is no fake approval flag or success stub. Source-flow deferral is distinct from delivery-attempt outcomes and is never stored as a fabricated attempt state. Simulator execution remains the existing explicit simulator workflow.

The worker reports claimed/processed and deferred counts separately, selecting only pending Moodle sources for the latter and preserving unrelated outbox work. It never back-fills a live attempt outside an authorized claim. Replay and reconciliation repair cannot advance deferred live work or reset its history. Manual commands retain active-role/capability and ordinary input checks; the gate precedes command-response replay so an old simulator success cannot stand in for a live result.

Connection health exposes separate write readiness. A healthy read-only identity check may coexist with `NOT_PROVISIONED` write readiness. Responses contain stable reasons only, without tokens, passwords, complete descriptors or raw credential-bearing URLs. The UI and own-registration projection must explain that access is being prepared and registration remains valid; historical simulator delivery does not prove current live access.
