## Failure, scope and proof

Distinguish pre-registration absence from service failure and neutral foreign-attempt absence. Refuse unknown publication states, empty published payloads, invalid dates or publication metadata, unrelated course sessions, inconsistent or unrelated history and ambiguous repeated request context. Do not fabricate activities, institutional authority, learning links or download capability.

The refresh button communicates checking and preserves context. A successful default read redirects once to its server-confirmed explicit attempt and period. A server-side `/auth/me` read establishes the current student actor; an opaque key binds that actor, attempt and period. Session storage retains only the confirmed read timestamp. After a service/transport failure, show “Last confirmed date” and “Current timetable unavailable”; remove all current courses, sessions and history. Different actors/attempts/periods, identity uncertainty and access/malformed-response failures cannot display another context's marker. Disabled/corrupt storage yields no marker and never changes current entitlement. No timetable response is cached.
