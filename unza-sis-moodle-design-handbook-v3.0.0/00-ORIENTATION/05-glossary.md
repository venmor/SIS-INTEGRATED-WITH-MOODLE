# Glossary

| Term | Meaning in this project |
|---|---|
| SIS | Authoritative Student Information System for institutional academic and administrative records |
| Moodle | Learning platform for teaching activity, submissions and provisional gradebook evidence |
| Active role | The role deliberately selected for the current workspace |
| Scope | Organization, programme, course offering, case, period or assignment within which a role applies |
| Journey | End-to-end experience of a role achieving a real goal |
| Action contract | Institutional, domain, application, UX and UI definition of one controlled action |
| State machine | Permitted lifecycle states and transitions for a governed record |
| Command | Intentional request to perform a validated action |
| Event | Versioned fact that an approved action occurred |
| Outbox | Reliable record used to publish external effects after a committed transaction |
| Idempotency | Protection that makes a retried request produce one intended result |
| Reconciliation | Comparison and controlled correction of SIS and external-system state |
| Policy version | Approved, effective-dated institutional rule set |
| Task packet | Small authoritative context bundle for one development task |
| ADR | Architecture Decision Record explaining a significant technical choice |
| Vertical slice | Small feature completed through UI, API, domain, data, security, tests and documentation |
| Presentation MVP | Connected, defensible subset that proves architecture and critical journeys |
| Operational completion | Declared scope proven under security, failure, recovery, accessibility, monitoring and UAT |
