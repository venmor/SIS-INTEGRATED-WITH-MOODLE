# Background, Problem and Rationale

University lifecycle work crosses admissions, academic registry, teaching, assessment, finance, student support, quality assurance and external reporting. When those functions are represented as unrelated forms or generic dashboards, users cannot tell who owns a task, what state a record is in, why an action is blocked or how a failed integration will recover.

Moodle adds a critical boundary. It is valuable for teaching and assessment evidence, but it must not become an uncontrolled source of official registration, results or progression. Payments and notification providers create the same risk: a callback or delivery response is evidence, not permission for a provider to change institutional decisions.

The project therefore focuses on controlled workflows rather than a collection of screens. Official records use explicit states, changes preserve history, permissions include scope and relationship, external effects are reconciled, and users receive plain-language status with a reason and next step. The rationale is both technical and human: institutional integrity depends on reliable boundaries, while user trust depends on clear journeys and recoverable errors.
