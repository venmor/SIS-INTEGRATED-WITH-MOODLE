# Limitations, Open Decisions and Conclusion

This handbook is a design baseline, not proof of implementation. Exact institutional policy values, final legal/privacy review, approved identity provider, hosting environment, production payment/notification providers, Moodle instance details, retention schedules and regulator formats must be confirmed before the related production task.

Composite role books organize approved material that appeared across several design records; any action still lacking explicit authority, state, visibility or tests must be resolved through the design-gap process before code is merged.

The project is intentionally constrained: no early microservices, Kubernetes, Kafka, Redis, chatbot or uncontrolled AI decision-making. These exclusions protect learning time and keep the presentation MVP defensible.

The design provides a coherent path from research to an operationally mature SIS–Moodle platform. Its central achievement is not a technology list; it is a traceable agreement between user experience, institutional authority, architecture, security, delivery and learning. Following the roadmap and evidence gates will let Charles and Chitindu build progressively without losing the approved patterns.
