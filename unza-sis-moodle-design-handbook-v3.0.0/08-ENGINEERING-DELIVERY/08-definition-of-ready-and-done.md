# Definition of Ready and Definition of Done

## Ready for implementation

- Approved release and requirement/action ID
- Role, scope, state and user outcome defined
- UI screen/component and all important states defined
- API/command/event and module ownership defined
- Data/configuration and migration impact understood
- Permission, denial, privacy and audit rules named
- Integration uncertainty/recovery named
- Tests and acceptance evidence named
- Lead developer, reviewer and learning goal assigned
- Explicit out-of-scope list

## Done for a feature

- Small cohesive implementation matches the task packet
- Formatting/type/static checks pass
- Unit and API/integration tests pass
- Authorization denial tests pass
- Critical browser/accessibility/recovery tests pass
- Audit/observability and error content are verified
- No secret, real personal data or hard-coded institutional policy
- Migration/contract changes are versioned and reversible where practical
- Module docs, traceability and learning note updated
- Other developer reviewed and can explain the change
- Staging/demo evidence captured

“The screen works on my laptop” is not done.
