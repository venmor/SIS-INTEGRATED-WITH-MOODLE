# High-Level to Code-Level Explanation Model

For every feature, both developers prepare a seven-layer explanation:

1. **Problem:** Who is blocked or at risk today?
2. **Policy:** Who may act, under which rule and state?
3. **Journey:** What does each user see and what handoff follows?
4. **Architecture:** Which module owns the action and which integrations observe it?
5. **Data:** Which records and constraints preserve correctness/history?
6. **Code:** Which components, controllers, services, guards and tests implement it?
7. **Evidence:** What tests, audit entries and demo prove it?

Use this order in learning notes, PR walkthroughs and presentation answers. It prevents memorizing code without understanding the system.
