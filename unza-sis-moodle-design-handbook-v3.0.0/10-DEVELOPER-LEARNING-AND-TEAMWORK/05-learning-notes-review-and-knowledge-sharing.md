# Learning Notes, Review and Knowledge Sharing

Each merged task creates a learning note using the template. The lead explains new concepts, one difficult decision, one error encountered and how evidence proved the outcome. The reviewer adds questions and confirms they can reproduce the flow.

Weekly, the team holds a short knowledge exchange:

- Demonstrate one user journey
- Draw its request/state/event flow
- Explain one permission denial
- Review one failure/recovery case
- Inspect CI/test evidence
- Identify codebase/documentation debt
- Swap next-slice roles

Presentation readiness is continuous: if only the original implementer can explain a feature, the learning handoff is incomplete.
