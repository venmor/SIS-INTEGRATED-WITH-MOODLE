# Accessibility, Usability and Low-Bandwidth Tests

Every critical journey is completed with:

- Keyboard only
- Representative screen reader
- Required zoom/reflow
- Narrow mobile browser
- Slow/intermittent connection
- Error identification/correction
- Visible focus and logical order
- Accessible sign-in/recovery
- Text/icon status, not colour alone
- Accessible table/chart alternative

Human acceptance should include representative applicants, students, assistive-technology users, lecturers/tutors, advisers, administrative/examinations/finance staff, support staff, QA/leadership and operations roles.

Usability evidence records task, participant type, completion, confusion/error points, recovery, accessibility issue, severity, fix and retest. A happy-path developer demonstration is not user acceptance.
